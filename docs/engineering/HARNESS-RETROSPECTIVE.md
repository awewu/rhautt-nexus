# Harness 工程学复盘（2026-08）

> 盘面：57 个守卫脚本 / 60 条 `guard:` 命令 / 台账 59 项（40 绿 · 0 红 · 19 环境跳过）。
> 本文每条结论都对应本仓库真实发生过的事件（提交号可溯），不是理论。

## 一、被实证有效的五个机制

### 1. 棘轮（ratchet）是对付存量债务的唯一诚实姿势
内联样式 2073 处、裸色值 451 处——一次清零不现实，禁新增又拦不住存量。
棘轮解法：**基线只准降不准升**。实证：内联样式 2073→1999→1997 逐次锁死；裸色值 451→431。
最有说服力的时刻是它**咬了建它的人两次**：死信面板 3 处裸色值被 `guard:ui-tokens` 拦下、
可抽取性卡片 3 处内联样式被前一天刚建的 `guard:inline-style-ratchet` 拦下。
**守卫不咬自己人，就是装饰品。**

### 2. 篡改测试是守卫的出生检
`geo-next-readiness` 与 `frontend-coverage` 上线前都做过：故意破坏被守护物 → 确认转红 →
恢复 → 确认转绿。没做这一步的守卫等于没测过的测试。
反面记录也保留：某次篡改脚本自身写坏（PowerShell 转义），当时如实记录"未证明失败路径"，
而不是宣称通过——**守卫的验证记录本身也要诚实**。

### 3. 失败分类（REAL / ARTIFACT / BROKEN）让红灯可分诊
台账不只报红，还回答"红的是业务、缺产物、还是守卫自己坏了"。
实证：分支合并后 3 个守卫报 `Cannot find module evidence-utils`——归类 BROKEN 而非业务问题，
5 分钟定位是分支未同步。没有分类，一片红只会导致"全都别信"。

### 4. 环境依赖显式登记，而不是永久豁免
本机 Redis 需密码 → 挂入 `ENV_DEPENDENT`（默认跳过、`--all` 仍执行、注明挂起日期）。
**跳过是一种带截止条件的状态，不是删除。** 19 个 SKIP 各有理由字符串，
与"注释掉失败的测试"有本质区别。

### 5. 豁免必须写理由，理由本身受审查
`frontend-coverage` 的豁免每条带原因，意外收益是**错误理由暴露了两笔假账**：
"gtm-digest 待接驾驶舱卡片"（实为 StratOS 机器端点，不该有界面）、
"通知走铃铛通道"（当时铃铛是无事件的死按钮）。修正时注明更正日期，
形成守卫系统自己的更正史。

## 三、方法论（一句话版）

1. **盲区要么被覆盖，要么被登记，不允许默默存在**——`unmeasured`/豁免清单/`ENV_DEPENDENT` 是同一原则的三个形态。
2. **守卫的职责是让问题可见，不是替人做决定**——可抽取性分低不拦发布、疑似重复只展示不合并。
3. **口径谦卑写进输出**——"字符串特征级，匹配上≠真用上""通过≠必被引用""前后对比不构成因果"。
4. **新守卫必须过篡改测试**，否则不许注册进台账。
5. **点估计不许下结论**——实验统计闸（Wilson/Newcombe + 最小样本）把"lift>0 即有效"废掉，
   是守卫哲学应用到业务指标本身。

## 四、结语

最诚实的一条总结：这两天守卫抓住了机器 4 次，人的眼睛抓住了守卫 2 次
（杜撰命名、悬空 tab 栏）。**守卫体系的上限不是替代人的验收，
而是让人的验收只需要花在守卫够不着的地方。**

据此新建三个守卫（2026-08-14 落地，见 `scripts/agent-guards/`）：
- `guard:seed-naming`（堵 F3）：种子迁移 SQL 中的品牌/站点中文名必须出自 brand-registry；
  废弃别名（如 瑞豪特）与已知杜撰名（瑞合舒适）任何位置出现即红。
- `guard:token-authority`（堵 F2）：对外站 app 层 `--brand-*` 与 `packages/tokens/*` 权威值
  逐值比对；已知漂移须显式登记待裁决，不许静默。
- `guard:layout-anchors`（堵 F4）：`position:fixed/sticky` 的锚定值登记成清单，
  新增/变更/删除锚定必须同步登记——改布局时有一张"谁锚着我"的账。
